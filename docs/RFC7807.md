# RFC 7807 Error Envelope

The API uses a consistent RFC 7807-style error payload for validation conflicts and other client-facing failures.

## Shape

Each error response includes:

- `type`: a stable URI identifying the error category
- `title`: a short human-readable summary
- `status`: the HTTP status code
- `detail`: a human-readable explanation of the failure
- `instance`: the request path that triggered the error
- optional extension members such as `errors` or `fields`

## Example

```json
{
  "type": "https://developer.apexchainx.io/errors/422",
  "title": "Validation Error",
  "status": 422,
  "detail": "The request body contains invalid fields.",
  "instance": "/api/v1/outages/",
  "errors": [
    {
      "field": "severity",
      "message": "Field required",
      "code": "missing"
    }
  ]
}
```

## Guidance

- Use the envelope for request validation failures and conflict responses.
- Keep the `detail` message concise and actionable.
- Preserve the `instance` path so clients can correlate the error with a specific route.
